# Build log: does it work yet?

## Shape

One episode of a build in progress. The founder says what they are making, where they are, and runs the test of the day on camera. The episode ends on whether it worked, and failures are shown as openly as wins.

## Beats

1. 0 to 2 s: the project in one line ("I'm building X to do Y").
2. 2 to 20 s: where we are. What passed last time, what is next.
3. 20 to 70 s: the test of the day, filmed live, with the result visible.
4. Last 10 s: worked or failed, what comes next, and a reason to follow for the next episode.

## Make it yours

Software builds can be filmed too: the bug of the day, the metric of the day, the feature that broke in testing. A founder of an AI voice agent runs a live call test each episode and shows whether the agent handled it. A founder building a robotics startup films each prototype test on the bench. A founder of a browser extension for researchers tracks daily active users and shows the dashboard each week. The series gives followers a reason to come back for the next result.

## Variations

- Failure episode: the test fails and the founder considers giving up (see the second example).
- Software log: screen recording of the bug or the metric of the day, with facecam in the corner.
- Countdown: episodes numbered toward a launch date.

## Why it works

Each episode leaves the build unfinished, so viewers return to see if it works next time (Zeigarnik 1927, open loops in series). A live test creates real suspense, and a shown failure surprises people used to polished launches.

## Watch out

- Keep tests real. A staged success destroys the trust the series builds.
- Hide customer data, keys and passwords on any screen you film.
- Hardware tests can be dangerous. Follow safety rules on camera, and warn viewers against copying risky steps.

## For your AI

```
Plan one episode of a 60 to 90 second "build log" series for [company], which is building [product] for [audience].
Where we are: [last result]. Today's test: [what we will try]. Result: [worked / failed / not yet known].
1. Write the one-line project recap for the opening, under 15 words.
2. Write the "where we are" beat in 2 sentences.
3. Write a shot list for the test of the day so the result is visible on camera.
4. Write two endings, one if it works and one if it fails, each with a reason to follow the next episode.
5. Add shot notes: on-site or screen recording, facecam for the recap.
Rules: real tests and real results, hide customer data and secrets on screen, flag risky steps, no invented numbers.
```
